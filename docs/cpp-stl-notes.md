## 一、`vector<int>` 内存模型与核心操作

`std::vector` 是连续内存分配的动态数组，底层由三个指针维护：`start`（起始地址）、`finish`（有效元素末尾）、`end_of_storage`（可用容量末尾）。

### 1. 函数签名中的引用传递 `&`
LeetCode 的函数签名通常如下：
```cpp
void merge(vector<int>& nums1, int m, vector<int>& nums2, int n)
```
- **`vector<int>& nums1`**：**必须传引用**。如果不加 `&`，传入的是实参的一份**完整内存拷贝**，函数内部对 `nums1` 的所有修改在函数返回后都会丢弃，导致评测判错。
- **只读传递**：若只需读取，推荐 `const vector<int>& nums`，避免 $O(N)$ 拷贝开销。

### 2. 下标访问 `[]` 与 迭代器 `iterator` 的严格区分
**常见初学者错误**：
```cpp
// ❌ 错误：混淆了下标与迭代器
nums1[nums1.begin() + x] 
```
- `nums1.begin()` 返回的是 **迭代器（Iterator）**，本质类似于指针。
- `nums1.begin() + x` 是迭代器偏移，解引用需使用 `*(nums1.begin() + x)`。
- `nums1[x]` 的参数必须是 **整数下标**（从 0 开始的整数）。
- **规则**：
  - 如果是指针/索引操作，直接写 `nums1[x]`。
  - 只有在配合 `insert`、`erase`、`sort` 等 STL 算法时，才使用 `nums1.begin() + x`。

## 二、`v.size()` 的 `size_t` 无符号下溢大坑

`vector::size()` 返回的是 `size_t`（在 64 位系统上通常是 `unsigned long long`，无符号整数）。

### 经典暴雷案例：
```cpp
// ❌ 极其危险的代码！
for (int i = 0; i < nums.size() - 1; ++i) { ... }
```
- **崩溃场景**：当 `nums` 为空时，`nums.size()` 为 0。
- `0 - 1` 在无符号运算下发生**下溢回绕**，结果会变成 `18446744073709551615`（即 $2^{64}-1$）！
- `i < 巨大数` 恒成立，循环开始执行并访问 `nums[0]`，瞬间触发**段错误（Segmentation Fault）**！

### 防御方案：
1. 强制转为整型：`for (int i = 0; i < (int)nums.size() - 1; ++i)`
2. 改写不等式：`for (int i = 0; i + 1 < nums.size(); ++i)`
3. 循环前先特判空：`if (nums.empty()) return ...;`

## 三、`resize()` vs `erase()` 的行为差异

刷数组题时，常常遇到“只保留前 $k$ 个元素”或“截断数组”的需求：

| 操作 | 语法 | 行为 | 内存容量（Capacity） | 潜在风险 |
| :--- | :--- | :--- | :--- | :--- |
| **`resize(k)`** | `v.resize(k);` | 将元素个数调整为 $k$ | 容量通常**不缩小** | 若 $k > v.size()$，会**自动补 0**！ |
| **`erase()`** | `v.erase(v.begin() + k, v.end());` | 删除 $[k, end)$ 区间 | 容量通常**不缩小** | 左闭右开，若漏写 `v.end()` 只会删单个元素 |
| **`clear()`** | `v.clear();` | 清空所有元素（$size=0$） | 容量保持不变 | 不会释放已分配的底层内存 |

### 警惕题目要求：
- 力扣中大部分题目（如第 27 题、第 26 题）明确说明：
  > “你不需要考虑数组中超出新长度后面的元素。”
- **原则**：题目只要求返回新长度 $k$，且前 $k$ 个元素正确即可，**切勿随意调用 `resize()`**。多余的 `resize()` 一旦长度算错直接判错，而且徒增运行时开销。

## 四、刷题时慎用 `insert()` 与 `erase()`

```cpp
nums.insert(nums.begin() + i, val); // 插入
nums.erase(nums.begin() + i);       // 删除
```
- `vector` 底层是连续数组，在中间 `insert` 或 `erase` 会导致后续所有元素整体搬迁，单次操作时间复杂度为 $O(N)$。
- 如果在循环中嵌套 `insert`，整个算法时间复杂度会飙升至 $O(N^2)$，极大可能超时（TLE）。
- **替代思路**：
  - 覆盖写入（快慢指针 / 双指针覆盖）
  - 倒序从后往前填充（利用尾部空闲区域）
  - 构造临时数组后统一赋值

## 五、指针/下标变量的命名防混淆原则

在双指针合并（如第 88 题）中，同时操作两个数组容易出现**变量混淆**：
```cpp
// ❌ 灾难性混淆：用 nums1 的指针 p 去取 nums2 的值
if (nums1[p] > nums2[q]) {
    nums1[x] = nums2[p]; // 应该赋 nums1[p]
} else {
    nums1[x] = nums1[q]; // 应该赋 nums2[q]
}
```

### 规范化防错命名：
1. **显式归属前缀**：
   - `p1` 代表 `nums1` 的读指针
   - `p2` 代表 `nums2` 的读指针
   - `tail` 或 `write_idx` 代表写指针
2. **赋值对照检查法则**：
   - 看到 `p1`，取值必为 `nums1[p1]`
   - 看到 `p2`，取值必为 `nums2[p2]`
   - 绝不允许 `nums1[p2]` 或 `nums2[p1]` 出现
