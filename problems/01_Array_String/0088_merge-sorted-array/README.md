## 1. 题目大意与核心约束

- **一句话题意**：给你两个按**非递减顺序**排列的整数数组 `nums1` 和 `nums2`，将 `nums2` 合并到 `nums1` 中，使 `nums1` 成为一个有序数组。
- **输入输出特征**：
  - `nums1` 的初始逻辑长度为 `m`，物理空间容量为 `m + n`，后 `n` 个元素为占位 `0`。
  - `nums2` 的长度为 `n`。
  - 函数返回 `void`，要求**原地（in-place）**修改 `nums1`。
- **关键约束**：
  - $0 \le m, n \le 200$
  - $1 \le m + n \le 200$
  - 数组可能存在单边为空的情况（$m=0$ 或 $n=0$）。

---

## 2. 初见直觉与思维瓶颈（心路历程）

### 阶段一：C++ 语法与 STL 初学困境
- **疑问**：
  - 函数签名里的 `vector<int>&` 为什么带 `&`？
  - `vector` 怎么取长度？为什么不能直接拿 `nums1.size()` 当做遍历长度？
  - 想截断或者只保留前 $x$ 位怎么做？能不能用 `resize`？
- **解答启发**：
  - `&` 是引用传递，修改直接作用到传入对象，不加 `&` 是值拷贝。
  - `nums1.size() == m + n`，而实际有效数据只有 `m` 个，后面 `n` 个是占位的 0。

### 阶段二：前向插入思维卡点
- 最初直觉是顺着数组从前往后比（从下标 0 开始）。
- 遇到了严峻阻碍：如果 `nums2` 的元素比 `nums1` 小，把 `nums2` 插入到前面，`nums1` 现有的元素就会被往后挤，必须用 `insert`，而且下标索引全乱了，时间复杂度也退化为 $O(N^2)$。

---

## 3. 中途错误代码与迭代轨迹（踩坑博物馆）

### 尝试 1：前向插入 + 迭代器与下标混淆
- **错误代码文件**：[solution_v1_wrong.cpp](solution_v1_wrong.cpp)
- **提交结果**：编译错误 (Compile Error)
```cpp
int x = 0, y = 0;
for (int i = 0; i < m + n; i++) {
    if (nums1[nums1.begin() + x] > nums2[nums2.begin() + y]) {
        nums1.insert(nums1.begin() + x, nums2[nums2.begin() + y]));
        nums1.pop_back();
    }
}
```
- **踩坑原因剖析**：
  1. **语法混淆**：`vector::operator[]` 接收的是整型下标，不能传入迭代器 `nums1.begin() + x`。
  2. **指针空转与漏处理**：只有小于时试图插入，但 `y` 未自增；等于或大于的情况完全没推进 `x`。
  3. **复杂度灾难**：在循环中使用 `insert` 会导致 $O(N^2)$ 复杂度。

---

### 尝试 2：逆向双指针，但比较逻辑颠倒 + 越界崩溃
- **错误代码文件**：[solution_v2_wrong.cpp](solution_v2_wrong.cpp)
- **提交结果**：解答错误 (Wrong Answer) / 运行时段错误 (RE)
```cpp
int p = m - 1, q = n - 1;
int x = m + n - 1;
for (int i = 0; i < m + n; i++) {
    if (nums1[p] > nums2[q]) {
        nums1[x] = nums2[q]; // ❌ 颠倒！
        x--; q--;
    }
    if (nums1[p] <= nums2[q]) {
        nums1[x] = nums1[p]; // ❌ 颠倒！
        x--; p--;
    }
}
```
- **踩坑原因剖析**：
  1. **比较方向反了**：从后往前填充，末尾位置 `x` 应该容纳**较大值**！代码却把较小值填入末尾，导致合并后逆序或错乱。
  2. **边界无保护**：循环直接固定跑 `m + n` 次，使用了两个平级的 `if`，且没有判断 `p >= 0` 和 `q >= 0`，当某一方先放完，另一方访问 `nums[-1]` 直接越界崩溃。

---

### 尝试 3：结构正确，但变量发生交叉混淆（Typo 杀手）
- **错误代码文件**：[solution_v3_typo.cpp](solution_v3_typo.cpp)
- **提交结果**：解答错误 (Wrong Answer)
```cpp
while (q >= 0) {
    if (p >= 0 && nums1[p] > nums2[q]) {
        nums1[x] = nums2[p]; // ❌ 灾难：用 nums1 的指针 p 去查 nums2！
        x--; p--;
    } else {
        nums1[x] = nums1[q]; // ❌ 灾难：用 nums2 的指针 q 去查 nums1！
        x--; q--;
    }
}
```
- **踩坑原因剖析**：
  - 思路和边界已经完全正确（`while (q >= 0)` 与 `p >= 0` 保护），但变量命名（`p, q, x`）缺乏语意，导致赋值时将数组与指针**交叉张冠李戴**。

---

## 4. 认知跃迁（Aha Moment）

> 💡 **核心破局点：逆向利用空闲缓冲槽位！**

1. **正向有冲突，逆向海阔天空**：`nums1` 后面空着 `n` 个位置，如果从末尾往前放，被比较出的“最大值”直接填入末尾，**绝不会覆盖到 `nums1` 前面尚未参与比较的有效数据**。
2. **`while (p2 >= 0)` 即可收工**：
   - 目标是将 `nums2` 彻底合并进去。如果 `nums2` 已经全部放置完毕（`p2 < 0`），而 `nums1` 还有剩余（`p1 >= 0`），这些剩余元素本来就在 `nums1` 的最前段，且原本就是升序排列好的，**根本不需要做任何搬移**！

---

## 5. 标杆最优解

- **代码文件**：[solution.cpp](solution.cpp)

```cpp
class Solution {
public:
    void merge(vector<int>& nums1, int m, vector<int>& nums2, int n) {
        int p1 = m - 1;         // nums1 有效部分的末尾
        int p2 = n - 1;         // nums2 的末尾
        int tail = m + n - 1;   // 整体写入位置（从后往前）

        while (p2 >= 0) {
            // 当 nums1 还有有效元素且比 nums2 当前元素大时，放 nums1[p1]
            if (p1 >= 0 && nums1[p1] > nums2[p2]) {
                nums1[tail--] = nums1[p1--];
            } else {
                // 否则（包含 p1 < 0 的情况），放 nums2[p2]
                nums1[tail--] = nums2[p2--];
            }
        }
    }
};
```

### 复杂度分析
- **时间复杂度**：$O(m + n)$，每个元素最多被读取并写入一次。
- **空间复杂度**：$O(1)$，仅使用了三个常数级的指针变量，完全原地修改。

## 6. 避坑 Checklist

- [ ] 指针命名是否清晰？（使用 `p1` 对应 `nums1`，`p2` 对应 `nums2`，避免用混）。
- [ ] 从后往前填充时，是否挑的是较大值？
- [ ] 是否在比较前检查了 `p1 >= 0` 防止数组下标下溢越界？
