## 1. 题目大意与约束

- **一句话题意**：给定一个非负整数数组 `nums`，初始位于数组的第一个下标（下标 0）。数组中的每个元素 `nums[i]` 代表你在该位置可以跳跃的最大长度。判断你是否能够到达最后一个下标。
- **核心约束与测试特性**：
  - $1 \le nums.length \le 10^4$
  - $0 \le nums[i] \le 10^5$
  - 数组元素表示的是“最大跳跃长度”，即在位置 $i$ 可以选择跳跃 $1, 2, \dots, nums[i]$ 步中的任意一步。
  - 特殊边界：$n = 1$ 时（起步即终点），直接可达；元素包含多处 `0` 时容易形成阻断壁障（例如 `[3, 2, 1, 0, 4]`）。

## 3. 错因深层复盘与认知跃迁

### 1. 致命手误：嵌套循环中更新变量写错（`i++` vs `j++`）
- **现象**：
  ```cpp
  for(int j=0; j<nums[i] && i+j<nums.size(); i++) // ⚠️ 致命笔误：末尾写成了 i++
  ```
- **危害**：
  在多层循环中，内层循环自增外层索引是一个极其隐蔽却极度致命的 bug。`j` 始终为 0，内层无法向前步进，外层 `i` 反复被累加或越界，直接导致代码在第 1 个测试用例上陷入死循环，力扣报出 `Time Limit Exceeded (0 / 178)`。
- **应对准则**：在写嵌套 `for` 循环头时，养成三段式强校验习惯：**声明的循环变量、判断条件的循环变量、步进的循环变量必须三者统一**。

---

### 2. 逻辑漏洞：跳跃物理语义与数组索引的偏差（`j=0` 与 `j<=nums[i]`）
- **漏洞 A：`j = 0` 导致“自身检测，自我赋权”**
  - 跳跃是物理位移，最小位移必须是 $+1$ 步（向前迈一步）。
  - 当 $j = 0$ 时，`nums[i + j]` 实际上就是 `nums[i]` 自己！
  - 只要当前位置 `nums[i] > 0`，内层就误判 `temp++`，即使后面全都是 0（死路），它也会把当前位置标记为“能够到达终点”。
  - **典型反例**：`nums = [1, 0, 0]`
    - 下标 2 为终点；
    - 下标 1 为 0（无法起跳）；
    - 下标 0 的值为 1，按题意只能跳到下标 1，整体应当返回 `false`。
    - 但由于 $j=0$ 检查了 `nums[0 + 0] = 1`，误把下标 0 标记为可达，错误返回 `true`。
- **漏洞 B：`j < nums[i]` 漏掉了最远跳跃落点**
  - 若 `nums[i] = 2`，合法的跳跃距离是 1 步或 2 步（可到达 $i+1$ 和 $i+2$）。
  - 写成 `j < nums[i]` 时，$j$ 只能取 1，导致最远的 $i+2$ 根本没有被探测，错失了本可以到达终点的路径。
- **破局**：跳跃步长必须严格定义在闭区间 $[1, nums[i]]$：
  ```cpp
  for (int j = 1; j <= nums[i] && (i + j) < nums.size(); j++)
  ```

---

### 3. 原地复用数组的 DP 状态设计与冗余开销
- **代码做法**：将 `nums[i]` 原地覆盖为 `temp`（能够跳到的可达后继点数量）。
- **潜在风险与冗余**：
  1. **含义污染**：在逆序遍历时，尚未处理的左侧元素需要读取右侧元素的“可达性”，但如果数组原地被改写，容易混淆“原始跳跃能力”和“是否可达”。幸好在此代码中，是从后往前单向依赖，且只根据 `nums[i+j] > 0` 来做判断。
  2. **冗余循环**：本题只需要判断**“是否存在至少一个后继点可达终点”**，只要发现某个 $i+j$ 已经可达，就可以立即 `break` 终止内层扫描，无需继续把剩余所有的 $j$ 都统计一遍（计算 `temp` 的总数对本题无任何额外收益，反而白白耗费 CPU 周期）。

---

### 4. 算法复杂度瓶颈（$O(N^2)$ vs $O(N)$）
- **当前解法性能**：运行时间 **650 ms**，仅击败 **5.01%**。
- **根源**：采用双重循环模拟自底向上转移，对于 $N = 10^4$ 的数组，最坏情况下运算量达到 $\approx \frac{N^2}{2} = 5 \times 10^7$ 次。力扣没有卡超时纯属数据规模在边缘，但这绝非面试与实战所期望的最优解。

## 4. 进阶标杆：两套 $O(N)$ 贪心范式（0 ms 击败 100%）

### 模型 A：顺延你的“倒序倒推”思路 —— 逆向贪心（维护最左目标点 `last_pos`）
你的初始构想（从后往前看谁能到达终点）非常敏锐！其实完全不需要双重循环，**只需要记录一个“已知能到达终点的最靠左位置 `last_pos`”**：

- **核心洞察**：
  1. 初始目标点是终点：`last_pos = n - 1`；
  2. 从倒数第二个元素往前遍历 $i = n - 2 \dots 0$；
  3. 如果当前位置 $i$ 的最远跳跃距离能覆盖 `last_pos`（即 $i + nums[i] \ge last_pos$），说明从 $i$ 出发一定能顺利到达 `last_pos` 并通往终点！
  4. 此时，到达终点的新“接力棒”就交给了 $i$，直接更新：`last_pos = i`；
  5. 遍历结束后，只需看起点是否拿到了接力棒：`return last_pos == 0;`。

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        int n = nums.size();
        int last_pos = n - 1; // 记录已知能通向终点的最左有效点
        
        for (int i = n - 2; i >= 0; i--) {
            // 只要能一步跳到（或跨过）已知的有效点，当前点就成为新的最左有效点
            if (i + nums[i] >= last_pos) {
                last_pos = i;
            }
        }
        
        return last_pos == 0;
    }
};
```
- **复杂度**：时间 $O(N)$（单次线性扫描），空间严格 $O(1)$。
- **性能**：**0 ms 击败 100%**！

---

### 模型 B：经典正向贪心 —— 最远可达边界扫描（`max_reach`）
从起点正向出发，实时维护一个全局最远能够到达的坐标：

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        int max_reach = 0;
        int n = nums.size();
        
        for (int i = 0; i < n; i++) {
            // 如果当前下标超过了此前所有点所能到达的最远边界，说明遇到了不可逾越的鸿沟
            if (i > max_reach) return false;
            
            // 贪心拓展最远边界
            max_reach = max(max_reach, i + nums[i]);
            
            // 剪枝：一旦最远边界已经能覆盖终点，提前返回
            if (max_reach >= n - 1) return true;
        }
        
        return true;
    }
};
```
- **复杂度**：时间 $O(N)$，空间严格 $O(1)$。
- **性能**：**0 ms 击败 100%**！

## 5. 总结与后续二刷建议

1. **第一关（语法习惯）**：嵌套循环切忌手滑混淆索引自增，写完循环头强制核对。
2. **第二关（物理模型）**：跳跃步长是相对位移（$+1 \dots +nums[i]$），不要从 0 开始自检，也不要写漏闭区间边界。
3. **第三关（思维升维）**：从后向前的“可达性转移”中，不需要统计每一个后继点，只要维护**最左侧的可达点**即可实现从 $O(N^2)$ DP 到 $O(N)$ 逆向贪心的降维打击！
